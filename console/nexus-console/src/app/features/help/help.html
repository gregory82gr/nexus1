STATIC REFERENCE — NO BACKEND CALL

This console is a demonstration/portfolio build layered on a real, intentionally partial .NET backend. It has no control authority over any real plant: every write path in this build is exactly one endpoint (alarm acknowledgement), and every other screen is read-only. Where a screen's underlying data does not exist yet, it says so directly rather than showing an invented value — that discipline is this console's actual subject, more than any single reading is.

Screen reference

  • Plant Overview / Plant Fleet — real per-unit power and cross-context status, aggregated from whichever contexts respond.
  • Reactor cluster (Core, Control Rods, Neutronics, Coolant/TH, Steam & Secondary, Kinetics) — one real generic signal feed per unit; Kinetics additionally derives reactor period from two consecutive real readings.
  • Training Mode — a genuinely simulated reactor model for drills, entirely separate from every live-telemetry screen.
  • Alarms & Events — the real alarm list and the one real write action this console exposes, acknowledgement.
  • Radiation / Safety, Power & Grid, Robotics, Asset/Inspection screens — each built from whatever this backend genuinely tracks for that domain; absent fields are named, not filled in.
  • Security / Services — real per-context database connectivity, explicitly not service-level health.
  • NX-Script Console — a read-only query interpreter over this same console state. It recognizes 14 named signals; most resolve to an honest "not tracked" refusal rather than a fabricated value. Act verbs (set, scram, hold, step, wait) are refused by design; acknowledge is refused as a real capability this console does not expose here. select uX changes the active unit for every screen on this console, not just this one.

Scope

Advisory and illustrative only. Nothing in this console issues a command to any real plant equipment, and no screen should be read as an operational safety system.
